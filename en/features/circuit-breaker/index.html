Circuit Breaker

The per-account circuit breaker stops 9Router from hammering an account that is clearly failing. When an account keeps erroring, the breaker "opens" and skips it for a cooldown — then probes it gently before trusting it again.

This rides inside the chat fallback loop, so when one account trips, your request simply lands on the next healthy account. You never see the failure.

How It Works

Account fails 5 times within 60s
        ↓
🔴 Breaker OPENS — account skipped for 60s
        ↓ cooldown expires
🟡 Half-open — exactly ONE real request admitted as a passive probe
        ↓
✅ Success → breaker closes, account fully back
❌ Failure → re-opens with cooldown ×2 (30s→60s→120s…, capped at 10 min)
  • Failure threshold: 5 account-level failures within a 60-second window (default).
  • Escalating cooldowns: each re-open doubles the cooldown, capped at 10 minutes.
  • Passive probe: a real user request serves as the probe — no synthetic traffic, and the user behind it is never sacrificed: if the probe fails, the request falls through to the next account.
  • No double-counting: quota-429s already handled by the antigravity strike-block are not counted as breaker failures.

When a breaker opens or recovers, the matching breaker-open / breaker-recovered alert fires (see Alerts).

Dashboard Panel

The panel shows open/half-open breakers, recent failure counts, cooldown countdowns, antigravity strike-blocks, and a manual reset button for when you've fixed the underlying issue and don't want to wait out the cooldown.

Manual reset via API:

POST /api/providers/{providerId}/breaker

Settings

SettingDefaultMeaning
breakerEnabledtrueKill switch — false restores pre-breaker behavior exactly
breakerFailureThreshold5Failures within the window before opening
breakerWindowSec60Failure-counting window
breakerBaseCooldownSec60First cooldown; doubles on repeated re-opens

Tune via Dashboard → Settings. If you suspect the breaker is misbehaving, flip breakerEnabled off — behavior is byte-identical to the old fallback loop.

When Breakers Trip

Typical causes worth investigating when you get a breaker-open alert:

  • Provider-side outage or degraded API (most common)
  • Expired/revoked OAuth token on that account
  • A proxy in front of the account dying (check the proxy pool)
  • Antigravity quota strikes (displayed in the panel, but not counted here)
