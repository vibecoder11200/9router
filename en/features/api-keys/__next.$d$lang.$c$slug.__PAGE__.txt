4:Tce9,# API Keys & Budgets

API keys gate access to your 9Router endpoint when **Require API key** is enabled. Keys are hashed at rest, and each key can carry its own spending budget with optional hard enforcement.

---

## API Key Security

- **Hashed at rest** — keys are stored as HMAC-SHA256 digests under a per-install secret (a `0600` file on your machine), never in plaintext. Legacy plaintext keys keep working and migrate lazily on first use.
- **Masked everywhere** — listings and the UI only ever show `sk-{keyId}-••••{last4}`. Exports/backups contain hashes, never raw keys.
- **Per-install secrets** — the hashing secret and the MITM sudo-password key are random per install; no machine-derived or hardcoded fallback.

> 📦 **Upgrading from an older version?** Take a DB backup before upgrading to a release with key hashing (`v0.6.36+`), and re-enter the MITM sudo password once after upgrade — old ciphertext is intentionally undecryptable under the new per-install key.

---

## Per-Key Budgets

Each key can set a budget so a runaway agent or a shared teammate can't burn your whole quota.

```
Dashboard → Endpoint & Key → ✏️ Edit key → Budget

Budget type:   USD  |  Tokens  |  Off
Limit:         e.g. 5 (USD) or 50,000,000 (tokens)
Window:        Daily  |  Monthly   (server-local time)
Soft threshold: 80%   → fires the budget-threshold alert once per window
Hard block:    ON/OFF → 429 with Retry-After when the limit is reached
```

### Behavior

| Moment | What happens |
|---|---|
| Spend < 80% of limit | Nothing — normal traffic |
| Spend ≥ soft threshold (default 80%) | One `budget-threshold` alert per window (edge-triggered, no spam); informational from 80% even without hard block |
| Spend ≥ limit **with hard block ON** | Request rejected with `429`, a `Retry-After` header pointing at the window end, and `X-9Router-Budget: limit-exceeded` |
| Window rolls over | Budget resets, alert re-arms |

Spend is read **fresh from usage history at enforcement time** (indexed query) — never a stale cache. Keys without a budget add zero queries to the hot path.

### Choosing USD vs Tokens

- **Token budgets are exact** — they count prompt + completion tokens.
- **USD budgets are estimates** — they sum recorded costs, which require pricing to be configured for the model. Models without pricing contribute $0, so USD budgets can under-count; the editor warns when a key's spend is dominated by unpriced models.

### Requirements & Caveats

- Budgets apply only when **Require API key** is enabled (enforcement lives in the key-auth path).
- Windows are computed in **server-local time**: daily = local midnight, monthly = 1st of month.
- The alert fires through the [Alerts](./alerts.md) system — configure a channel to receive it.

## Creating & Managing Keys

```
Dashboard → Endpoint & Key

+ Create key  →  sk-... shown ONCE (copy it immediately)
✏️ Edit       →  rename, budget, active toggle
🗑 Delete     →  immediate revocation
```

Use one key per tool or per person (e.g. `cursor-laptop`, `cline-desktop`, `teammate-anh`) so usage rows and budgets stay attributable.
