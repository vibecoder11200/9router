API キーと予算

Require API key を有効にすると、API キーが 9Router エンドポイントへのアクセスを制御します。キーは保存時にハッシュ化され、各キーには任意でハード強制付きの予算を設定できます。

API キーのセキュリティ

  • 保存時にハッシュ化 — キーはインストールごとのシークレット（マシン上の 0600 ファイル）による HMAC-SHA256 ダイジェストとして保存され、平文では決して保管されません。レガシーの平文キーもそのまま動作し、初回使用時に段階的に移行します。
  • あらゆる場所でマスク — 一覧と UI は sk-{keyId}-••••{last4} のみ表示。エクスポート/バックアップにはハッシュのみ含まれ、生キーは含まれません。
  • インストールごとのシークレット — キーのハッシュ化と MITM sudo 暗号化のシークレットは各インストールでランダム生成。マシン由来やハードコードされたフォールバックキーはありません。

📦 旧バージョンからのアップグレード? キーハッシュ化（v0.6.36+）を含むリリースに更新する前に DB をバックアップし、更新後に MITM sudo パスワードを一度再入力してください。旧暗号文は新しいキーでは意図的に復号できません。

キーごとの予算

暴走するエージェントや共有メンバーがクォータを使い果たすのを防ぐため、各キーに予算を設定できます。

Dashboard → Endpoint & Key → ✏️ キー編集 → Budget

予算タイプ:   USD  |  トークン  |  オフ
上限:         例: 5 (USD) または 50,000,000 (トークン)
ウィンドウ:   日次  |  月次   （サーバーローカル時刻）
ソフトしきい値: 80%   → ウィンドウごとに 1 回 budget-threshold アラートを発火
ハードブロック: ON/OFF → 上限到達で 429 + Retry-After

動作

状況何が起きるか
支出 < 上限の 80%通常どおり
支出 ≥ ソフトしきい値（デフォルト 80%）ウィンドウごとに 1 回 budget-threshold アラート（エッジトリガー、スパムなし）
支出 ≥ 上限 ハードブロック ON429 で拒否、ウィンドウ終了を指す Retry-After ヘッダー、X-9Router-Budget: limit-exceeded
ウィンドウ切替予算リセット、アラート再武装

支出は強制時に使用履歴から直接（インデックス済みクエリ）読み取られ、古いキャッシュは使われません。予算未設定のキーはホットパスにクエリを一切追加しません。

USD かトークンか

  • トークン予算は正確 — プロンプト + 完了トークンを数えます。
  • USD 予算は推定 — 記録されたコストの合計であり、モデルに価格設定が必要です。価格未設定のモデルは $0 と計上されるため過少計上になり得ます。価格未設定モデルが支出の大半を占める場合はエディターが警告します。

条件と注意

  • 予算は Require API key が有効な場合のみ機能します。
  • ウィンドウはサーバーローカル時刻で計算: 日次 = ローカル午前 0 時、月次 = 1 日。
  • アラートはアラートシステム経由で届きます。チャネルを設定してください。

キーの作成と管理

Dashboard → Endpoint & Key

+ 作成  →  sk-... は一度だけ表示（すぐコピー）
✏️ 編集  →  名前変更、予算、有効切替
🗑 削除  →  即時失効

ツールや人ごとにキーを分けると（例: cursor-laptop）、使用履歴と予算の帰属が明確になります。
