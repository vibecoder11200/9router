## 告警与通知

真实通知通过**告警**系统（Dashboard → Alerts）送达，支持 Telegram、Discord 和通用 webhook 渠道 —— 没有邮件。见[告警指南](./alerts.md)。

### 你实际会看到的事件

```
⚠️ quota-near-limit
   Claude Code: 已用 82%（2 小时后重置）

🚨 budget-threshold
   Key sk-abc123…•789: 每日预算 $4.10 / $5.00（82%）

🔴 breaker-open
   cx/gpt-5.6-sol: 60 秒内 5 次失败 —— 跳过 60 秒

🔴 all-accounts-locked
   glm 所有账号被限流；无法服务请求
```

相同事件 10 分钟内去重。每种事件可单独开关。

### 按 Key 预算

预算按 API key 设置（见 [API Key 与预算](./api-keys.md)）：

- 每日/每月窗口的 USD 或 token 预算
- 软阈值（默认 80%）每窗口触发一次 `budget-threshold` 告警
- 可选硬阻断在限额处返回 `429` + `Retry-After`

## 熔断器与节点健康

Quota 页面还有两个运维面板：

### 熔断器面板

按账号显示打开/半开的熔断器、失败数和冷却倒计时，附手动重置按钮。故障账号自动跳过 —— 见[熔断器](./circuit-breaker.md)。

### 缓存分析

使用表格包含 **Cached** 和 **Cached Cost** 列，统计负载还携带按 provider/model 的缓存块：

- **缓存 token** 和估算**命中率**（cached ÷ prompt token）
- **估算节省** —— 这些缓存 token 若不缓存本应花费多少，基于已配置价格（未定价模型显示 n/a，绝不显示假的 $0）


## 最佳实践

### 1. 每日监控配额

```
日常:
1. 查看仪表盘配额概览(30 秒)
2. 检查重置时间
3. 根据配额可用性规划使用
```

**示例:**
```
早晨检查:
  ✅ Claude Code: 5h 可用(刚重置)
  ✅ Antigravity: 1K 请求可用
  ⚠️ GLM-4.7: 剩 2M tokens(10AM 重置)
  
行动: 早上工作用 Claude Code
```

### 2. 设置预算上限

```
仪表盘 → 设置 → 预算:
  每日: $5(防止超支)
  每月: $150(与预算对齐)
```

**结果**:达到上限时自动切换到免费层。

### 3. 优化组合使用

```
仪表盘 → 分析 → 组合:
  查看哪些模型用得最多
  调整组合顺序以最小化成本
```

**示例:**
```
当前: cc/claude-opus-5 → glm/glm-4.7
  80% 通过 Claude(好)
  20% 通过 GLM($12/月)

优化后: ag/gemini-3-flash → cc/claude-opus-5 → glm/glm-4.7
  50% 通过 Antigravity(免费)
  40% 通过 Claude(订阅)
  10% 通过 GLM($6/月)
  
节省: $6/月
```

### 4. 跟踪重置时间

```
仪表盘 → 配额 → 重置日程:
  Claude Code: 5h 滚动 + 每周一
  Antigravity: 每日 00:00 UTC + 每月 1 日
  GLM-4.7: 每日 10:00 AM 北京时间
  MiniMax: 5h 滚动窗口
```

**策略**:配额刚刷新时使用对应提供商。

### 5. 查看月度报告

```
仪表盘 → 分析 → 月度报告:
  总 tokens: 1.5B
  总成本: $120
  节省: 相比 ChatGPT API 节省 97%
  
洞察:
  - 60% 用量来自订阅($0)
  - 30% 通过 GLM($90)
  - 10% 通过免费层($0)
  
优化:
  - 增加 Antigravity 用量(免费)
  - 减少 GLM 用量(更贵)
```

## 故障排除

**问题:配额显示 0% 但请求失败**

**方案:**
1. 检查提供商连接(仪表盘 → 提供商)
2. 确认 API keys 有效
3. 检查提供商是否宕机(状态页)
4. 尝试重新连接 OAuth 提供商

**问题:成本估算不正确**

**方案:**
1. 仪表盘 → 设置 → 定价
2. 确认每个提供商的定价与当前一致
3. 若提供商调整费率,更新定价
4. 若差异持续,联系支持

**问题:重置时间没有更新**

**方案:**
1. 刷新仪表盘(F5)
2. 检查系统时间是否正确
3. 确认时区设置
4. 若问题持续,重启 9Router

**问题:未收到告警**

**方案:**
1. Dashboard → Alerts —— 确认渠道已配置并启用
2. 点击渠道的 **Test** 按钮
3. 检查事件类型是否被关闭
4. Telegram 场景：机器人必须能向你的 chat ID 发消息
